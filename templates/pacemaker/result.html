pacemaker_setup.sh (pcs commands)
Every resource and constraint is wrapped in an skip-if-it-already-exists guard, so the script is safe to re-run. To change a definition, tear it down first with pacemaker_teardown.sh below — re-running this script will skip resources that already exist, so edits alone will not take effect.
CIB XML snippet (for reference)
inventory.yml (Ansible)
deploy_pacemaker.yml (Ansible Playbook)
Run: ansible-playbook -i inventory.yml deploy_pacemaker.yml
pacemaker_teardown.sh (unregister)
The counterpart to the script above. Run this first when you want to change a definition and re-apply. It removes things in reverse dependency order (constraints → groups → services/FS → DRBD → STONITH) and skips anything that is missing, so it is safe to re-run. It does not touch DRBD volume data or LINSTOR resources — it only unregisters them from Pacemaker.
pacemaker_maintenance.sh (rolling patch/reboot, one node at a time)
Follows the §5.1 procedure per node: standby → release versionlock and patch → reboot → unstandby. It pauses for confirmation (Enter) at two points — right after standby and at the final check — so it is not unattended automation.
Running it manually 
# 1. Copy and run the script (on the first node)
scp pacemaker_setup.sh root@node1:/tmp/
ssh root@node1 "bash /tmp/pacemaker_setup.sh"

# 2. Check cluster status
pcs status
pcs resource show
pcs constraint show

# 3. Check DRBD status
drbdadm status

# 4. Check the Quadlet services
systemctl status myapp.service
All set. Your DRBD + Quadlet + Pacemaker HA container cluster configuration is complete. If something goes wrong, check pcs status and journalctl -xe.
